Performance through the TS API

Time with the Rust engine as a multiple of TS concerto-core 5.0.0 (× TS; below 1× is faster than TS), grouped into five kinds of operation. Each chart has one line per representative operation (up to four). Each point is one task's measurement run, plotted at the median across the model sets that run reported (test data, conformance models, synthetic large model, or the 500-instance workload). Log scale.

Ratios are strictly comparable only within one run: the lines join different runs, on a laptop (hollow points) or a cloud container (filled points). Only merged work is shown. Lines use TS-API figures only; where a task measured several routes, the default resident or warm path is plotted. Crate-level (native Rust vs TS) figures, such as P5-48's, appear in the tables with their level. Unmerged spikes and superseded figures stay in perf.json. Decorator and DCS operations (decorateModels, extractDecorators, extractVocabularies, DCS validate, getDecorators) are included in the introspection chart, which draws two introspection and two decorator lines; its table lists every operation. No operation fell outside these five categories, so there is no "other" chart.

Bugs found in TypeScript concerto-core

Behaviours of TS concerto-core 5.0.0 that the migration identified as bugs, drawn from DIVERGENCES.md, BREAKING-CHANGES-PLAN.md, the post-migration issues and the fuzzing triage. By default the Rust engine reproduces TS behaviour for parity. Since the maintainer chose a single major release on 29 Sep (R3 folded into R1), most planned fixes moved into R1. A final group lists bugs found in the migration's own layers, which are not TS 5.0.0 bugs. Impact is the risk rating given in the breaking-changes plan.
